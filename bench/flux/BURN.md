# flux against Burn's autodiff

Generated by `examples/flux_burn.rs` (Burn 0.21) and `bench/flux/compare_jax.py` (the XLA rows), on the inputs
`examples/flux_programs.rs` writes: AMD Ryzen 9 7900, one core (process affinity), f32, median times. Every Burn
result is checked against flux's interpreter (largest difference relative to the largest value).

- Burn has no compiled loop: a recurrence is a few tensor ops per sample on its autodiff tape (about 1 µs per
  step forward, 74 µs per step with the backward pass). flux turns the scan into one `stablehlo.while`.
- Burn's `rfft` / `irfft` have no autodiff rules yet (`todo!` in burn-autodiff 0.21), so its spectral model uses
  DFT matrix products (O(n²) per frame) and the STFT-loss model would need the same for three resolutions on
  top of a 2048-step tape.
- flux on XLA pays a compile once (31 ms for the one-pole, 0.1-0.5 s for the others); Burn runs eagerly.
- flux's interpreter evaluates the traced graph op by op, allocating arrays per step: a reference, not the
  fast path (its scan is 2.4 µs per step, slower than Burn's eager forward).
